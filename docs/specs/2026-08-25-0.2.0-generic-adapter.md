# 0.2.0 — a generic payment adapter

**Date:** 2026-08-25
**Status:** designed, not yet implemented
**Package:** `@mimu-sh/ownable-payments` (breaking `0.x` minor). `@mimu-sh/ownable-core` is
unchanged and gets no changeset.

---

## Why

`0.1.x` was extracted from exactly one application, and it shows in three places. A second
consumer (`throwacoin`, a wishing fountain selling three fixed-price coin tiers) cannot use
the package as written:

1. **`DodoConfig.productId` assumes one product.** throwacoin has three, one per tier, chosen
   per request from stored server-side state.
2. **`PaymentEvent` hardcodes `slug` and `ownerId`.** throwacoin has neither. It keys on a
   uuid `wish_id`.
3. **`verifyWebhook` returns `PaymentEvent | null`,** where `null` collapses bad signature,
   tampered body, timestamp out of tolerance, wrong event type, non-USD currency and absent
   metadata into one value. This is not a theoretical loss: stillthinking's webhook route
   re-verifies the payload a *second* time with a raw `standardwebhooks` call purely to find
   out whether a dropped event was a genuine paid non-USD charge worth logging. That
   workaround is the bug report.

There is also a fourth item this release closes, from stillthinking's `HANDOFF.md` open item
6: **`brand_id` filtering**, deferred with the condition *"if several mimu.sh products share
one Dodo account"*. A second product makes that condition true.

## The API delta

### `verifyWebhook`

```ts
// 0.1.x
verifyWebhook(raw: string, headers: Record<string, string>): Promise<PaymentEvent | null>

// 0.2.0
verifyWebhook(raw: string, headers: Record<string, string>): Promise<VerifyResult>

export type PaymentEventKind = 'payment' | 'refund'

export type PaymentEvent = {
  kind: PaymentEventKind
  providerEventId: string
  amountCents: Cents
  currency: string                    // surfaced, never silently dropped
  metadata: Record<string, string>    // opaque; no slug/ownerId in the type
}

export type VerifyResult =
  | { ok: true; event: PaymentEvent }
  | {
      ok: false
      reason: 'unverifiable' | 'ignored_type' | 'ignored_brand' | 'wrong_currency'
      diagnostic?: {
        providerEventId?: string
        type?: string
        currency?: string
        amountCents?: number
        brandId?: string
      }
    }
```

`WebhookConfigError` is unchanged and still thrown, not returned — it is a different kind of
problem from any per-event outcome, and the distinction is load-bearing.

### `DodoConfig`

```ts
export interface DodoConfig {
  apiKey: string
  webhookSecret: string
  apiBase?: string                                 // unchanged; still defaults to LIVE
  acceptCurrencies?: readonly string[]             // new; default ['USD']
  eventKinds?: Record<string, PaymentEventKind>    // new; default payment.succeeded -> payment,
                                                   //               refund.succeeded  -> refund
  brandId?: string                                 // new; unset means no filtering
  // productId: REMOVED — moved to createCheckout
}
```

### `createCheckout`

```ts
export type Pricing =
  | { mode: 'product' }                       // fixed-price product; Dodo charges its own price
  | { mode: 'server'; amountCents: Cents }    // PWYW + Single Payment; cart item carries amount

createCheckout(i: {
  productId: string
  pricing: Pricing
  metadata: Record<string, string>
  returnUrl: string
}): Promise<{ url: string }>
```

## Design decisions, and what they are defending against

**The USD guard stays in the library, but stops being silent.** Moving currency policy wholly
to consumers was considered and rejected: a dropped non-USD event is a *real charge* the
application never learns about. The default-on guard remains; it now returns
`reason: 'wrong_currency'` carrying the payment id, currency and amount, which is everything
stillthinking's second verification was re-deriving. `acceptCurrencies` makes the policy
visible and overridable rather than welded in.

**Metadata presence is NOT enforced.** `0.1.x` returned `null` when `slug` or `ownerId` was
missing. That is now the caller's check, because throwacoin needs a `refund.succeeded` event
*even when metadata is absent* — that is the branch where it logs "the provider did not
replay metadata, this item cannot be un-listed". A `requiredMetadata` option would eat the
event before the application could log it. Missing metadata is trivially checkable by a
caller with no risk of silent loss; a wrong currency is not, which is why the two are treated
differently.

**Pricing regimes are stated, not assumed.** `0.1.x` always wrote `amount` into the cart item.
That is correct only for a Pay-What-You-Want, Single Payment product — against a fixed-price
product the amount is ignored and the product's own price is charged (stillthinking
`HANDOFF.md` open item 3). An optional `amountCents?` would hide that; a discriminated union
forces a caller to say which regime its product is in and turns a mismatch into a type error
rather than a silently ignored field. The adapter cannot inspect the product's configuration,
which is exactly why the caller must assert it.

**`apiBase` keeps defaulting to live.** Unchanged from `0.1.x`, and reaffirmed: a deployment
silently stuck in test mode hands out real goods for no money with nothing failing anywhere,
while a live host holding a test key throws on the first call.

## Migration guide for `0.1.x` consumers

```ts
// config
- createDodoAdapter({ apiKey, webhookSecret, productId, apiBase })
+ createDodoAdapter({ apiKey, webhookSecret, apiBase })

// checkout
- adapter.createCheckout({ slug, ownerId, amountCents, returnUrl })
+ adapter.createCheckout({
+   productId,
+   pricing: { mode: 'server', amountCents },   // or { mode: 'product' }
+   metadata: { slug, ownerId },
+   returnUrl,
+ })

// webhook
- const ev = await adapter.verifyWebhook(raw, headers)
- if (!ev) return new Response('ignored', { status: 202 })
- use(ev.slug, ev.ownerId)
+ const r = await adapter.verifyWebhook(raw, headers)
+ if (!r.ok) {
+   if (r.reason === 'wrong_currency') console.error('paid event dropped', r.diagnostic)
+   return new Response('ignored', { status: 202 })
+ }
+ const { slug, ownerId } = r.event.metadata
+ if (!slug || !ownerId) return new Response('ignored', { status: 202 })  // now the caller's check
```

A consumer that does not handle refunds should pass
`eventKinds: { 'payment.succeeded': 'payment' }` to keep `0.1.x` behaviour, where
`refund.succeeded` was simply not a recognised event.

## Tests to write first

TDD. These fail before the implementation exists.

- `verifyWebhook` returns `ok: false, reason: 'unverifiable'` for a bad signature, a tampered
  body, and a timestamp outside tolerance.
- `ignored_type` for a verified event whose type is not in `eventKinds`, and the default map
  recognises both `payment.succeeded` and `refund.succeeded`.
- A custom `eventKinds` narrows the set — `refund.succeeded` becomes `ignored_type`.
- `wrong_currency` for a verified `payment.succeeded` in EUR, **with** `providerEventId`,
  `currency` and `amountCents` present in `diagnostic`. This is the regression guard for the
  defect that motivated the release.
- `acceptCurrencies: ['USD','EUR']` accepts EUR.
- `ignored_brand` when `brandId` is set and the payload's brand differs; no filtering when
  `brandId` is unset; `diagnostic.brandId` carries the rejected value.
- Metadata absent -> still `ok: true` with `metadata: {}` (the refund case).
- `WebhookConfigError` still thrown for an empty and for a malformed secret, and is NOT a
  `VerifyResult`.
- `createCheckout` with `mode: 'server'` puts `amount` **inside** `product_cart[0]` and not at
  the top level; with `mode: 'product'` the cart item has **no** `amount` key at all.
- `createCheckout` pins `billing_currency: 'USD'` in both modes.
- `productId` comes from the call, not from config, and two calls can use different ones.
- The adapter reads no `process.env`.

Existing `0.1.x` tests in `packages/payments/test/dodo.test.ts` are rewritten against the new
shapes; `packages/payments/test/classify.test.ts` is untouched.

## Release

`pnpm changeset` -> **minor** on `@mimu-sh/ownable-payments` only. Then a human dispatches the
`Release` workflow (`workflow_dispatch`); npm provenance is signed by the OIDC token in CI.
Publishing is not automated and is not done from a developer machine.

Do not publish until `stillthinking` has migrated against a local link and its suite is green
— that migration is the acceptance test for this API.

## Deliberately out of scope

- **`@mimu-sh/ownable-db`.** A second consumer now exists, which was the condition
  stillthinking's `HANDOFF.md` item 7 set for extracting `fulfil`. It is still deferred, by
  decision, until the adapter boundary has held up in two applications. `fulfil` is the
  single most dangerous function in either app and does not move on a hunch. When it does
  move, `normalizeOwnerId` and the integer-cents guard must go with it.
- Anything in `@mimu-sh/ownable-core`. throwacoin uses `usd` and nothing else from it; the
  ruleset and `slugify` do not apply to a fixed-tier product and must not be stretched to fit.
